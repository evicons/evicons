# Acceptance: v0.9

Scope: the new package `@evicons/vue` and the Iconify and Vue documentation, listed in the 0.9.0 section of [`CHANGELOG.md`](../../CHANGELOG.md). No icon was added or changed; all 84 icons keep their geometry and approval.

## Delegation

Since 2026-11-01 the owner (Landolsi Digital) delegates the design decisions to the maintainer. The owner decided on 2026-11-17 to ship Vue components (issue #1); the API (props, fall-through attributes, slot, accessibility rules, `vue@^3.5.0` for `useId`) was set by the maintainer to match `@evicons/react`.

## Checks

| Check | How | Result |
|---|---|---|
| Same icons and exports as React | `tools/build-icons.ts` writes the same module text to `packages/vue/src`; `tests/build-icons.test.ts` compares the checked-in Vue and React sources file by file | identical, 84 modules plus aliases |
| Component behaviour | `packages/vue/test/create-ev-icon.test.ts` mirrors the React tests: defaults, size and stroke, class merge, fall-through attributes and listeners, `title`, `aria-label`, `aria-labelledby`, explicit `aria-hidden` and `role`, slot order, `absoluteStrokeWidth`, prop updates, kebab-case props in templates | pass |
| Server rendering | `vue/server-renderer`: unique `<title>` ids referenced by `aria-labelledby`; every icon of the built package renders on the server (`tests/consumer/smoke-vue.test.ts`) | pass |
| Package | built `dist`, tree shaking of the root import, deep import `@evicons/vue/icons/<name>`, plain Node ESM, `package.json` export, node10 type lookup, TypeScript check of `h()` calls with valid and invalid props | pass |
| Website | Vue snippet on every icon page (English and German from the same component) and as a tab in the gallery panel, docs section `#vue`, home page start line; Playwright site suite and visual suite in the Playwright image | pass |

Template type checking with `vue-tsc` could not be run: `vue-tsc` 3.3 does not support TypeScript 7, which the repository uses.

## Release note

`@evicons/vue` is a new npm package. Trusted Publishing can only be configured for a package that exists, so the owner publishes 0.9.0 of `@evicons/vue` once by hand (with 2FA) and then adds the GitHub release workflow as its trusted publisher; the release workflow skips versions that are already on npm.
